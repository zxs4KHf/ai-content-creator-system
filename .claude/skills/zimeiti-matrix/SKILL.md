# 自媒体矩阵实验

把“感觉某条会爆”改写成单变量、可覆盖、可复盘的实验。

## 先读

1. `00_账号定位/账号定位.md`
2. `91_知识库/K9_内容特征学习与账号矩阵实验.md`
3. `01_想法库/矩阵实验池.md`
4. `01_想法库/外部样本特征池.md`
5. `01_想法库/矩阵实验数据.csv`
6. 复盘时再读 `91_知识库/K4_数据诊断表.md`

## 设计实验

1. 用 T7 写清实验类型：`pilot` 只跑流程，`discovery` 只找值得继续测的栏目组合，`controlled` 才做单变量因果实验；再填写 ID、假设、固定项、变体、平台、观察窗、主指标与安全指标。
2. 每变体默认至少 3 条；48 小时和 7 天各记录一次。
3. 先在一个孵化号内测试栏目。单条爆款、样本不足或尚无原创库存时，不建议拆号。
4. 涉及外部内容时用 `T11_外部样本特征卡.md`；只保留 URL、观察时间和抽象功能笔记，不下载视频、不存逐字稿、不把作品作为改写底稿。
5. 在内容生产前完成八项原创差异审计；事实/版权/声音权利存疑时停止进入 G2。
6. 把计划写入 `01_想法库/矩阵实验池.md`，然后停在既有 G1/G2/G3 门，不自行越门。

## 收集与校验数据

逐条写入 `01_想法库/矩阵实验数据.csv`；后台没有的字段留空，不推算。运行：

```powershell
python 92_工具箱/matrix_tracker.py 01_想法库/矩阵实验数据.csv --min-samples 3
```

修正脚本报告的结构错误。覆盖警告未消失前，只记录观察，不宣布胜者。不同平台、不同观察窗和不同形式不得合并成一个万能分数。

## 作出决定

- 至少 3 条形成一个单元；优先看同平台同形式的滚动中位数。
- 只有观看、转发/收藏、关注三组中至少两组重复胜出且无安全问题，才追加 3 条。
- 下一条只继承一个胜出变量，并重新创作人物、目标、障碍、因果链、结局和视听表达。
- 单条同时在留存与价值指标进入最近 10 条前 20% 时，可规划同母题新故事、同结构新母题和幕后复盘；7 天没有复现，不写入永久规则。
- 任一版权、声音权利、AI/虚构漏标或平台安全问题立即停更复审，不等待样本量。

## 写回飞轮

1. 更新具体实验卡和 `矩阵实验池.md` 的状态/结论。
2. 用 `zimeiti-review` 的诊断顺序定位内容问题。
3. 只把有足够样本的结论写回 `01_想法库/选题库.md`、`90_模板库/` 或 `91_知识库/`。
4. 在 `93_运行记录/决策日志.md` 记录改前、改后、样本和理由。
5. 达到拆号门槛时，先核验当日平台实名、账号数量和营利规则；注册和登录由用户在可见本地页面完成。

## 并行边界

- 可以并行：不同实验/内容的独立诊断、不同公开来源的一手规则核验。
- 必须主 Agent 收敛：去重、跨实验归因、永久规则修改、账号拆分建议。
- 同一 CSV、选题库、模板或决策日志只由主 Agent 写入，避免冲突。

## 质量检查

- [ ] 只有一个主要变量，固定项明确
- [ ] 每变体样本覆盖达标；不足时没有宣布规律
- [ ] 没有跨平台万能总分
- [ ] 外部作品只做抽象特征学习，原创差异审计通过
- [ ] 安全信号没有被高播放抵消
- [ ] 结论已经写回文件，而不是只留在回答中
