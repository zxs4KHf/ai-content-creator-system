# 数据复盘（飞轮）

## 这个 skill 解决什么

复盘最常见的失败不是分析得不对，是**分析完什么都没改**。这个 skill 的核心约束是：**没有落实为文件修改的复盘，视为未完成。**

## Step 0：先读

1. `91_知识库/K4_数据诊断表.md` —— 症状 → 病因 → 处方对照表（本 skill 的主要依据）
2. `04_已发布/` —— 待复盘的内容
3. `01_想法库/选题库.md` —— 权重调整的目标
4. `91_知识库/K9_内容特征学习与账号矩阵实验.md` 与 `01_想法库/矩阵实验数据.csv` —— 涉及栏目/账号实验时读取

## Step 1：拿数据

复盘节奏：**发布后 48 小时和 7 天各记一次。**

用户贴数据即可，格式不限。需要的字段：

| 平台 | 发布时间 | 播放/阅读 | 赞 | 藏 | 评 | 转 | 涨粉 | 完播率/读完率 |
|---|---|---|---|---|---|---|---|---|

拿不到完整数据时，**优先要这三个**：抖音看完播率、小红书看收藏率、公众号看打开率。其余可缺。

## Step 2：按诊断顺序定位（不要跳步）

```
① 有没有曝光？  → 没有 = 账号/合规问题，不是内容问题
② 有曝光，留不住人？ → 钩子问题（前 3 秒）
③ 留得住，看不完？   → 中段问题（节奏/信息密度）
④ 看得完，不点赞？   → 价值感/选题问题
⑤ 点赞了，不评论？   → 形式问题（内容太闭环）
⑥ 点赞了，不转发？   → 选题问题（不能替观众表达身份）
⑦ 都不错，不涨粉？   → 人设/系列化问题
```

对照 K4 的三张表（短视频 / 图文 / X）找到对应行，**在复盘里明确引用是哪一行**。

涉及实验时先运行：

```powershell
python 92_工具箱/matrix_tracker.py 01_想法库/矩阵实验数据.csv --min-samples 3
```

只比较同平台、同观察窗、同形式的分组中位数。覆盖不足只记录观察，不宣布胜者，不生成跨平台万能分数。

**归因铁律**：内容质量 80% / 账号 5% / 发布时间 5% / 未知 10%。
→ 不要写"可能是发布时间不对"。除非同一条内容在两个时间段各发过一次并有对照数据，否则时间不是解释。

## Step 3：三问（写进 `数据复盘.md`）

1. **哪里超预期？为什么？**
   要具体到"是钩子起作用还是选题起作用"。不接受"内容质量好"这种回答。

2. **哪里拉胯？卡在哪一环？**
   必须给出 K4 诊断表的具体行。

3. **下一条要改什么？**
   **必须落实为一处具体修改**，二选一（也可以两个都做）：
   - 调整 `01_想法库/选题库.md` 里某个选题的分数——写明从几分改到几分、哪个维度、为什么
   - 修改 `90_模板库/` 或 `91_知识库/` 里的某一条规则——写明改了**哪个文件的哪一行**，改前改后各是什么

## Step 4：落实修改（这一步才是飞轮）

**直接改文件，不要只写建议。** 改完在复盘末尾附一段变更记录：

```
## 本次落实的修改
- 91_知识库/K1_钩子公式库.md 第六节：金句字数上限从 15 字改为 12 字
  依据：本条金句 14 字，小红书封面显示被截断
- 01_想法库/选题库.md S3 成本分：4 → 3
  依据：实际生图 18 张（预估 8 张），成本严重低估
```

同时把变更追加到 `93_运行记录/决策日志.md`，一行一条，带日期。**这份日志是账号的记忆**——半年后你会想知道为什么当初定了某条规则。

## Step 5：样本量警告（很重要）

- **单条数据不构成结论。至少 3 条同类内容表现一致，才动选题库权重。**
- 爆款只能继承一个被重复验证的抽象变量；人物、情节链、脚本、画面和声音不得批量换皮。
- 前 10 条处于冷启动期，绝对值无参考价值，**只看相对值**（这条比上条好还是差）。
- 涨粉是滞后指标，不要用它做短期决策。

如果样本不足，复盘照做，但**明确写"样本不足，本次不改权重，仅记录观察"**，不要为了凑一个"落实修改"而乱改规则。

## 定位复审（每 10 条一次）

积累 10 条发布数据后，做一次账号定位复审。**这个不是常规复盘，是更大的动作**：

1. 汇总 10 条的数据，按内容线（知识线 / 故事线）和平台分组
2. 回答四个问题：
   - 两条内容线的表现差距有多大？要不要调整配比？
   - 平台矩阵里哪个是真正的主阵地？和原计划一致吗？
   - "双线交叉"这个差异化点，观众感知到了吗？（看幕后内容的互动率）
   - 人设与语气有没有需要调整的？
3. 更新 `00_账号定位/账号定位.md`，**版本号 +0.1，注明复审日期和依据**
4. 旧版本追加到文件末尾的历史区，不要直接覆盖

## 并行调度

| 环节 | 并行 | 说明 |
|---|---|---|
| 多条内容各自诊断 | ✅ 并行 | 每条一个 subagent，按 K4 定位 |
| 跨条找规律 | ❌ 主 Agent | 需要全局视野，subagent 各看各的会得出矛盾结论 |
| 落实修改 | ❌ 主 Agent | 涉及文件写入，必须集中做避免冲突 |

## 质量自检

- [ ] 每条内容都定位到了 K4 诊断表的具体行
- [ ] 三问都回答了，且答案具体（不是"内容质量好/不好"）
- [ ] **至少一处文件修改已实际执行**，不是只给建议
- [ ] 变更已追加到 `93_运行记录/决策日志.md`
- [ ] 样本不足时明确说明了，没有硬凑结论
- [ ] 矩阵实验通过覆盖校验，且没有跨平台万能分数
- [ ] 没有把问题归因给发布时间（除非有对照数据）
