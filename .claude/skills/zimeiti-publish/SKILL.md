# 全平台发布（阶段④）

## 一鱼多吃原则

**核心资产（正文 + 分镜 + 图）只生产一次，以下全部是"改编"，不是重写。** 永不为单一平台单独生产。

## Step 0：先读

1. `91_知识库/K2_平台规格手册.md` —— **这是硬约束表，逐条对照**
2. `91_知识库/K3_叙事结构模板.md` —— 各平台的默认结构
3. `91_知识库/K6_AI合规红线.md` —— 发布前合规自检
4. `00_账号定位/账号定位.md` —— 平台矩阵与各平台角色

## Step 1：并行改编（六个平台六个 subagent）

每个 subagent 拿到：核心正文 + 分镜 + 素材清单 + **该平台的 K2 规格段落**，独立产出。用 `90_模板库/T3_多平台改编模板.md`。

主 Agent 负责统一金句与钩子——**同一条内容在六个平台的金句应该是同一句**，subagent 各写会散掉。

### 各平台要点速记

| 平台 | 关键约束 | 结构 |
|---|---|---|
| **抖音/视频号** | 标题 15-20 字 ｜ 标签 3-6 ｜ 竖版 1080×1920 ｜ 封面文案大字 7 字内 ×2 行 | S-1 / K-1 |
| **小红书** | **标题必须 18-20 字**（上限 20，不要浪费）｜ 图 1080×1440 ≤9 张 ｜ **标签 3-5 个写在正文内** ｜ 正文 300 字内 | 知识线一律 **K-3 清单体**（拉收藏率） |
| **公众号** | 标题用足 30-50 字（上限 64）｜ 摘要 ≤120 字 ｜ 正文 15-16px 行距 1.75-1.8 配色 ≤3 种 | 长文 + **作者手记**（固定栏目：这条是怎么用 AI 做的） |
| **B站** | 5-10 分钟 ｜ 封面 1146×717 ｜ **前 15 秒讲清价值点** ｜ 章节时间轴 | **X-1 正片 + 幕后** |
| **X** | 首条 ≤140 中文字 ｜ **外链放首条回复不放正文** ｜ thread 4-8 条 | 钩子推 → 一图一段 → 金句推 → 回复补工作流 |

### 三条容易忘的

1. **小红书标题写满 18-20 字**并塞 2-3 个关键词。上限是 20，写 12 字是浪费曝光位。
2. **公众号标题不要复用小红书标题**。71% 阅读来自消息列表，标题就是全部，20 字太少。
3. **视频号要专门设计"值得好友点赞"的点**——好友点赞会直接进入其"朋友"栏曝光，绕过算法，这是抖音没有的路径。

## Step 2：产出发布物料清单

用 `90_模板库/T6_发布物料清单.md`。目标：**每一项都能直接复制粘贴，零二次加工。**

## Step 3：停在 G3

跑完 `91_知识库/K6` 的 G3 合规自检 + `K2` 第七节的规格自检，**逐条勾**，然后汇报：

```
《标题》已到 G3。

规格自检：11 项全过 / 第 X 项存疑：……
合规自检：9 项全过

发布物料：六平台齐备，无占位符残留
建议发布顺序：小红书（试错场，先发看收藏率）→ 抖音 → 其余跟随

请确认"G3 通过"，或指出要返工的部分。
```

**汇报后停下等人。**

## Step 4：发布（仅在人明确确认后）

### 铁律

**任何发布动作必须先经人确认，绝不自作主张发出去。** 这不是礼貌问题——发出去撤不回来。

**云端会话一律不碰登录态。** 所有需要 cookie 的发布服务只在用户本地 Windows 会话执行。跨境 IP + 代理出口访问平台 = 账号风险。

### 已接的三条通道

| 通道 | 覆盖 | 部署 |
|---|---|---|
| **xiaohongshu-mcp** | 小红书图文/视频发布、搜索、评论 | Go 单二进制跑在本地，`claude mcp add --transport http xiaohongshu-mcp http://localhost:18060/mcp` |
| **Wechatsync** | 一稿同步 29+ 平台（知乎/微博/头条/掘金/B站…），复用你自己的登录态调官方接口 | Chrome MV3 扩展，2.x 自带 CLI + MCP |
| **md2wechat** | 公众号：markdown 转排版 + 推草稿箱 | `convert --draft`。⚠️ 公众号 API 需 **IP 白名单**，只能从固定 IP 的本机发 |

部署步骤见 `92_工具箱/发布服务部署.md`。

### 无法自动化的部分

抖音/视频号的视频发布仍需手动。原因：浏览器自动化对抗平台风控是易碎件，同类开源项目已衍生出多个第三方"修复版"分支，说明上游跟不上平台前端改版。**不把核心链路押在易碎件上。** AI 的责任是把物料准备到"打开发布页只需复制粘贴"的程度。

### 公众号的两个坑

1. **IP 白名单**：当前 IP 必须登记在公众号后台。动态 IP 需要固定出口。
2. **草稿箱优先**：2025-07 后未认证账号越来越只能走草稿箱模式。推草稿 → 你在后台点发布，这也正好是最后一道人工门。

## Step 5：归档

G3 通过并发布后：`02_制作中/xxx/` 整个文件夹移入 `04_已发布/`，并新建 `数据复盘.md`（空模板），等 48 小时后填数据。

**状态即位置**：文件夹在哪，状态就是什么。不要用标记位。
