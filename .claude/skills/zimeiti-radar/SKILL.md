# 选题雷达（阶段①）

## 这个 skill 解决什么

想法多、落地少，是自媒体最常见的死法。这个 skill 把"想法"变成"可执行的选题对象"，并且**只让人做一件事：在 Top 5 里勾选**。

核心结构：**并行扫多源 → 硬过滤（不跑题）→ 归并去重 → 四维软打分 → 人只看 Top N**。

## Step 0：先读这三个文件（不可跳过）

1. `00_账号定位/账号定位.md` —— 一切生产的依据，红线在这里
2. `91_知识库/K7_选题雷达源.md` —— 雷达源清单、硬过滤规则、打分标准、并行调度规范
3. `01_想法库/选题库.md` —— 现有选题，用于去重

顺带读 `91_知识库/K1_钩子公式库.md` 和 `K3_叙事结构模板.md`，因为每条选题都要标注钩子编号和结构编号。

## Step 1：并行扫描（fan out 到 subagents）

默认扫这六个源，**每源一个 subagent，一次性全部发出，不要串行**：

| Subagent | 源 | 任务 |
|---|---|---|
| R1 | 收集箱 | 读 `01_想法库/收集箱.md` 待整理区，逐条抽取为原始想法 |
| R2 | 公开热榜 | 搜微博/知乎/抖音热榜与 AI 圈资讯，按硬过滤规则筛 |
| R3 | 长尾关键词 | 挖"AI 教程/AI 故事/AI 绘画"相关搜索与下拉词，找搜索量大供给少的 |
| R6 | 历史复盘 | 读 `04_已发布/` 的复盘结论，输出该加码/该放弃的方向 |
| R7 | 换位思考 | 从利益/兴趣/情感/猎奇四角度各出 2 条 |
| R10 | 元内容 | 检查本流水线近期跑通了什么环节，出幕后选题 |

R4（对标账号拆解）和 R5（评论区挖需求）需要平台登录态，**只在用户明确说"在本地跑"时才做，且每周不超过一次**。云端会话一律跳过，并在汇报里说明跳过了。

## Step 2：归并（必须在主 Agent 做，不能交给 subagent）

subagent 各自看不到对方的结果，直接汇总会产出大量近似重复。主 Agent 负责：

1. **硬过滤**：命中 K7 的"排除组"（政治/灾难/明星/股票/医美等）直接进淘汰区并写原因
2. **去重**：与现有选题库逐条比对，相似的**合并而非新增**（把新角度补进已有选题的"一句话方向"）
3. **补全**：给每条补钩子候选（K1 编号）和叙事结构（K3 编号）

## Step 3：并行打分

每条选题一个 subagent，按 K7 的四维独立打分：**契合 / 需求 / 成本 / 差异**，各 1-5 分，满分 20。

打分纪律（违反即重打）：
- 同一批里必须有高有低，**禁止全给 4 分**
- 每个维度必须附一句话理由，**没理由的分数无效**
- 总分 ≥15 进 G1 候选；12-14 进观察区；<12 淘汰并写原因

## Step 4：写盘

写入 `01_想法库/选题库.md`，按内容线分表、按总分降序。每条用 K7 第四节的最小结构（含钩子候选、结构编号、互动钩子、四维分与理由、来源）。

同时把 `收集箱.md` 里已处理的条目从"待整理"移到"已整理归档"，标注进入选题库的编号。**收集箱待整理区处理完必须清空**——不清空下次会重复处理。

## Step 5：停在 G1

向用户汇报，格式固定：

```
本轮扫了 N 个源，新增 X 条、合并 Y 条、淘汰 Z 条（原因分布：…）

【Top 5 候选】
1. [S6] 最后一位图书管理员 · 故事线 · 16 分
   钩子 B4 悬念提问 ｜ 结构 S-3 静物凝视
   为什么值得做：（一句话）
   风险：（一句话，没有就写"无"）
2. …

请勾选要做的（可多选），或说"都不满意，重扫"。
```

**汇报后停下等人。** 不要自作主张开始写方案——那是 G1 门的意义。

## 常见变体请求

| 用户说 | 怎么做 |
|---|---|
| "理一下收集箱" | 完整跑 Step 1-5 |
| "加一条想法：xxx" | 只追加到收集箱待整理区，不触发全流程，回一句"已记下，攒够了说'理一下收集箱'" |
| "从选题库挑 3 个出方案" | 这是 G1 通过的信号 → 交给 `zimeiti-script` |
| "这周做什么" | 只读选题库，按总分和时效性推荐，不重新扫描 |
| "重扫，要更大胆的" | 重跑，但打分时把"差异"维度权重视为双倍 |

## 质量自检

- [ ] 六个云端源都真的扫了（不是凭记忆编的）
- [ ] 每条选题都有钩子编号 + 结构编号 + 互动钩子
- [ ] 每个分数都有一句话理由
- [ ] 与现有选题库做过去重比对
- [ ] 淘汰的都写了原因（避免以后重复提出）
- [ ] 收集箱待整理区已清空归档
- [ ] 汇报里明确说明了跳过哪些源、为什么
