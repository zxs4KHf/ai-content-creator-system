# K7 · 选题雷达源

> **阶段①「想法池与调研」的作业指导书。** AI 按本文件并行扫描多个源，归并去重后写入选题库。
> 核心结构：**正则硬过滤（不跑题）+ LLM 软打分（排序）+ 人工只看 Top N**。

## 三、软打分（LLM 评分，1-5 分制）

| 维度 | 定义 | 5 分 | 1 分 |
|---|---|---|---|
| **契合** | 与账号定位/内容线的契合度 | 双线交叉，只有我们能做 | 换个账号发也一样 |
| **需求** | 目标受众的共鸣或实用需求强度 | 评论区有人主动问 | 我们自己觉得有趣 |
| **成本** | 制作成本，**分越高成本越低** | 当天能出（≤2h + ≤6 张图） | 要一周 |
| **差异** | 同类内容的供给饱和度，**分越高越蓝海** | 全网几乎没有 | 已经烂大街 |

**总分 = 契合 + 需求 + 成本 + 差异，满分 20。**

> ⚠️ 相比旧版三维打分，新增了 **差异** 维度。原因：前三维会系统性偏向"安全但同质"的选题，差异维度是唯一能把蓝海选题顶上来的机制。

**打分纪律**：
- 分数是**相对的**，同一批想法里必须有高有低，禁止全给 4 分
- 每个维度的分数必须附**一句话理由**，不写理由的分数无效
- 总分 ≥15 才进入 G1 候选；12-14 存入观察区；<12 直接淘汰并写原因

## 四、选题对象的最小结构（不是一句话）

一条合格的选题**不是一个标题**，必须是一个带钩子和结构的对象：

```yaml
id: S6
线: 故事线
选题: 最后一位图书管理员
一句话方向: AI 能回答一切的时代，谁还需要图书馆——答案 vs 过程
钩子候选: [B4 悬念提问, B5 视觉冲击]     # 引用 K1 编号
结构: S-3 静物凝视                        # 引用 K3 编号
互动钩子: 结尾问"你最后一次去图书馆是什么时候"
契合: 5  # 双线交叉：故事本身+AI取代人的母题
需求: 4  # 情绪共鸣强，但非刚需
成本: 4  # 8 镜，无新角色，可复用现有画风
差异: 3  # 同类"AI 取代人"故事不少，但图书馆角度较少
总分: 16
状态: 候选
来源: R1 收集箱 2026-07-26
```

**没有钩子候选和结构的选题，G1 一律打回。**

## 五、并行调度规范（AI 执行时）

```
阶段①「理一下收集箱」的标准执行：

1. 主 Agent 读 00_账号定位 + 本文件 + 现有选题库（拿到已有选题用于去重）
2. 并行 fan out：每个雷达源一个 subagent
   ├─ subagent-R1: 读收集箱待整理区，输出原始想法列表
   ├─ subagent-R2: 扫公开热榜，按硬过滤规则筛，输出候选
   ├─ subagent-R3: 挖长尾关键词，输出蓝海词 + 对应选题
   ├─ subagent-R6: 读已发布复盘，输出"该加码/该放弃"的方向
   ├─ subagent-R7: 四角度换位思考，各出 2 条
   └─ subagent-R10: 检查本流水线近期跑通了什么，出元内容选题
3. 主 Agent 归并（这一步必须在主 Agent 做，需要跨源全局视野）：
   ├─ 硬过滤：命中排除组的直接进淘汰区
   ├─ 去重：与现有选题库比对，相似的合并而非新增
   └─ 补全：给每条补钩子候选与结构编号
4. 并行打分：每条选题一个 subagent 独立打四维分 + 理由
5. 主 Agent 排序 → 写入 01_想法库/选题库.md → 收集箱已处理条目移入归档区
6. 停在 G1，向人汇报 Top 5 并等待勾选
```

**为什么归并必须在主 Agent 做**：去重需要看到所有源的全部结果，subagent 各自看不到对方，会产出大量近似重复。

## 六、起号期的特别规则

前 10 条内容处于冷启动，选题策略与稳定期不同：

- **控制变量法**：一次只改一个变量（钩子 / 结构 / 画风 / 时长），否则数据无法归因
- **先抄后超**：拆解已验证的爆款因子组合，先复现再改进。"别凭感觉猜，让数据告诉你答案"
- **小红书先发**：生产最快，用它验证选题，跑通了再做视频版
- **系列化优先**：能延伸 5 期以上的选题优先于孤立的好点子
- 三条起号路径任选：① 爆款内容起号 ② 流量内容起号（话题讨论/干货知识/趣味科普）③ 人设化内容起号

## 七、工具（可选，非必需）

| 工具 | 用途 | 备注 |
|---|---|---|
| **TrendRadar** | 聚合多平台热榜 + 关键词筛选 + AI 打分，支持 MCP 与 GitHub Actions 定时 | ✅ 只吃公开热榜、不碰登录态，**是唯一可以安全放在云端跑的选题工具** |
| 巨量算数 / 5118 | 关键词搜索量 | 网页手动查 |
| 小红书搜索下拉框 | 最真实的长尾词来源 | 手动，成本最低效果最好 |
| 新红 / 蝉妈妈 / 飞瓜 | 对标账号数据 | 付费，起号期不必要 |

**起号期结论：不要上任何工具。** 收集箱 + 热榜 + 搜索下拉框 + 评论区，四个源手动跑，足够支撑前 30 条内容。工具是量产期的事。
