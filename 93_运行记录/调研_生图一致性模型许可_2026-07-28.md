# 调研：生图一致性模型许可分层核验（2026-07-28）

> 状态：官方资料核验记录，不是法律意见。
>
> 范围：IP-Adapter / ComfyUI_IPAdapter_plus / IP-Adapter-FaceID / InstantID / PuLID / InsightFace 与 antelopev2 / FLUX.2 `[dev]` / Qwen-Image-Edit-2511。只使用项目或组件维护者的官方仓库、官方模型卡、官方许可证和厂商文档；没有下载权重、运行模型或调用 API。

## 一、判定方法

每条路线拆成七层，任一层未闭环都不能仅凭“开源”二字进入商业成片：

1. **代码许可**：推理代码、节点或 SDK 能否用于商业场景。
2. **权重许可**：适配器、checkpoint、LoRA、量化权重是否另有限制。
3. **底模许可**：SDXL、FLUX、Qwen 等基础模型单独适用什么条款。
4. **依赖许可**：人脸编码器、文本编码器、VAE、OpenCLIP 和其他模型权重是否放行。
5. **输出商用**：许可证是否限制输出，以及生产模型的运行本身是否获授权。
6. **维护状态**：是否正式归档/弃用，不能把“最近提交较旧”自动写成“已死”。
7. **核验日期**：许可证和模型卡会变，结论只对 2026-07-28 所见官方页面负责。

## 二、逐项结果

### 1. 通用 IP-Adapter 与 ComfyUI_IPAdapter_plus

| 层 | 核验结果 |
|---|---|
| 代码许可 | 腾讯 AI Lab 官方 IP-Adapter 仓库为 Apache-2.0；`cubiq/ComfyUI_IPAdapter_plus` 节点为 GPL-3.0。 |
| 权重许可 | 官方仓库指向的 `h94/IP-Adapter` 模型卡标 Apache-2.0。FaceID 权重是另一条路线，不能混入本结论。 |
| 底模许可 | 官方示例使用 SD 1.5 / SDXL 等；实际底模必须单独核验。适配器 Apache 标签不能覆盖底模。 |
| 依赖许可 | 通用 IP-Adapter 使用 OpenCLIP 图像编码器，需保留其依赖清单。`ComfyUI_IPAdapter_plus` README 明确说 **FaceID models** 需要 InsightFace，反证通用版并非全部依赖 InsightFace。 |
| 输出商用 | 只有当适配器、底模、编码器、参考图和输出内容权利都闭环时，才可判定具体生产链；不能仅凭适配器 Apache 标签下结论。 |
| 维护状态 | `ComfyUI_IPAdapter_plus` 作者在 2025-04-14 明确设为 maintenance-only，并表示不计划持续开发，但仍可能合并关键更新。腾讯主仓最近公开提交为 2024-06-28，未见正式归档或弃用声明。 |
| 项目决策 | 不再把“通用 IP-Adapter”写成已死或从根上不可商用；不把 maintenance-only 节点作为新默认。 |

**关键区分：**`IP-Adapter plus-face` 只是用裁剪后的人脸图作 CLIP 条件，不等同于 `IP-Adapter-FaceID`。是否调用 InsightFace 应以所选模型 ID 和工作流为准。

### 2. IP-Adapter-FaceID

| 层 | 核验结果 |
|---|---|
| 代码许可 | 代码位于 Apache-2.0 的 IP-Adapter 上游仓库。 |
| 权重许可 | 官方 `h94/IP-Adapter-FaceID` 模型卡明确：因为依赖 InsightFace 预训练模型，FaceID 模型只用于研究，不打算用于商业用途。 |
| 底模许可 | 官方示例使用 SD / SDXL 和社区底模，均需逐项核验。 |
| 依赖许可 | 需要 InsightFace `buffalo_l` 等预训练人脸模型；InsightFace 官方将其免费预训练模型限定为非商用研究。 |
| 输出商用 | 标准免费链未取得商业放行。 |
| 维护状态 | 随 IP-Adapter 上游；FaceID 模型卡没有持续维护承诺。 |
| 项目决策 | 商业生产排除，除非取得覆盖 FaceID 权重、InsightFace 模型和底模的书面许可。 |

### 3. InstantID

| 层 | 核验结果 |
|---|---|
| 代码许可 | 官方 GitHub 仓库为 Apache-2.0，并称代码可用于学术与商业。 |
| 权重许可 | [CONFLICT] Hugging Face 页面头部显示 Apache-2.0，模型卡正文也泛称项目采用 Apache；但同一项目官方 GitHub Disclaimer 明确写 released checkpoints are also for research purposes only。保守合规采用更具体、更严格的 checkpoint 声明。 |
| 底模许可 | 官方快速示例加载 SDXL；替换成其他底模时另审。 |
| 依赖许可 | 官方安装与示例要求 InsightFace `antelopev2`。该预训练模型按 InsightFace 官方政策仅限非商用研究。 |
| 输出商用 | 标准免费链未闭环，不能把代码 Apache 标签当作商业成片授权。 |
| 维护状态 | 官方仓库最近公开提交 `2145b67f`，时间为 2024-07-18；未见正式归档/弃用声明。 |
| 项目决策 | 商业生产排除。依据是 checkpoint 与依赖权重限制，不是“2024 年后就失效”。 |

### 4. PuLID

| 层 | 核验结果 |
|---|---|
| 代码许可 | 官方仓库 Apache-2.0。 |
| 权重许可 | 官方 `guozinan/PuLID` 模型卡头部标 Apache-2.0，包含 PuLID SDXL 与 FLUX 适配器权重。 |
| 底模许可 | SDXL 分支和 FLUX 分支必须分开；PuLID-FLUX 使用的 FLUX `[dev]` 权重不能因 PuLID 自身 Apache 标签而变成商业许可。 |
| 依赖许可 | 官方代码 `pulid/pipeline.py` 导入 InsightFace，下载并加载 `antelopev2`；因此标准管线受 InsightFace 预训练模型非商用研究限制。 |
| 输出商用 | 标准免费管线未闭环。理论上换成自有/已授权的人脸模型并选择合格底模后可重审，但兼容性和效果尚未验证。 |
| 维护状态 | 官方 GitHub API 显示最近公开提交 `1aa2fc7d`，时间为 2025-07-31，内容为支持 FLUX.1-Krea-dev；不能再写“2024-10 后停滞”。未见正式归档。 |
| 项目决策 | 商业生产暂缓；不是否定代码或权重本身，而是标准端到端管线缺少商业依赖闭环。 |

### 5. InsightFace 与 antelopev2

| 层 | 核验结果 |
|---|---|
| 代码许可 | InsightFace 主仓及 Python Library 代码为 MIT，官方明确代码不限制学术或商业使用。 |
| 权重许可 | 官方明确：由其提供的训练数据和预训练模型仅限非商用研究；手动下载和自动下载都执行同一政策。Python Library 的 Model Zoo 列出 `antelopev2`，并在表后再次说明这些模型仅限非商用研究。 |
| 底模许可 | 不适用。 |
| 依赖许可 | 可加载用户自有模型；但把兼容的商业人脸模型替换进 InstantID/PuLID 后是否保持嵌入空间与质量，需要工程验证。 |
| 输出商用 | MIT 代码不限制商业使用，但免费预训练权重并未放行商业生产。官方提供联系渠道获取特定模型的商业许可。 |
| 维护状态 | 主项目仍活跃；维护状态不会改变已有权重许可。 |
| 项目决策 | 可使用代码配合自有/已授权模型；不得把免费 `antelopev2` 当成商业可用依赖。 |

### 6. FLUX.2 `[dev]`

| 层 | 核验结果 |
|---|---|
| 代码许可 | 官方 `black-forest-labs/flux2` 推理仓库 Apache-2.0。 |
| 权重许可 | FLUX `[dev]` Non-Commercial License v2.0；免费授权只覆盖非商业、非生产用途。商业生产运行需另购自托管许可或使用符合商业条款的 API。 |
| 底模许可 | FLUX.2 `[dev]` 自身即底模，不能用代码仓 Apache 标签覆盖模型权重许可。 |
| 依赖许可 | 官方仓库列出 Mistral-Small-3.2-24B-Instruct-2506 作为文本编码/提示扩写模型，其官方模型卡为 Apache-2.0；FLUX.2 VAE 由 BFL 单独列为 Apache-2.0。使用远程编码器、量化包或其他组件时另审。 |
| 输出商用 | 许可证第 2(d) 明确允许输出用于包括商业在内的用途，但同时第 2(a)/(b) 限制模型运行只能用于非商业目的，并要求内容过滤或人工审核、依法进行 AI 标识。因此“所有输出禁商用”是错误的，“可在商业生产中免费自托管”同样错误。 |
| 维护状态 | 官方活跃。 |
| 项目决策 | 当前排除**未取得商业自托管许可的本地生产运行**；保留未来购买许可或合规 API 的可能。 |

**家族区别：**BFL 官方仓库把 FLUX.2 `[klein]` 4B 与 4B Base 列为 Apache-2.0，并称约 8GB VRAM 可运行；9B 与 `[dev]` 使用非商用许可。任何记录都必须带完整模型 ID，不能写“Flux 禁商用”。

### 7. Qwen-Image-Edit-2511

| 层 | 核验结果 |
|---|---|
| 代码许可 | 官方 `QwenLM/Qwen-Image` 仓库 Apache-2.0。 |
| 权重许可 | 官方 `Qwen/Qwen-Image-Edit-2511` 模型卡头部与 License Agreement 均为 Apache-2.0。 |
| 底模许可 | 自身为 Qwen-Image 编辑模型；不需要另套一个非商用图像底模。 |
| 依赖许可 | 官方 Qwen2.5-VL-7B-Instruct 模型卡为 Apache-2.0；实际 Diffusers、Transformers、VAE、量化加载器和运行时仍要在制品清单记录具体版本。LightX2V 官方 2511 Lightning 权重仓与模型卡标 Apache-2.0。 |
| 输出商用 | Apache-2.0 没有附加非商用用途限制；仍须由发布者承担输入图片授权、肖像/商标/版权、输出侵权审查和 AI 标识。 |
| 维护状态 | 官方仓库活跃；2511 权重于 2025-12-23 发布。 |
| 项目决策 | 是本项目许可相对清晰的本地质量候选，但只对**官方权重链和已逐件核验的依赖**成立。 |

官方模型卡显示 Qwen-Image-Edit-2511 为 20B BF16，未公布 8GB/12GB/16GB 的最低显存表。因此：

- 不把第三方 GGUF 文件大小直接写成官方显存承诺；
- 当前 RTX 3060 Ti 8GB 不宣称能直接运行官方 BF16；
- 第三方 GGUF / FP8 / ComfyUI 重打包必须分别核验派生来源、许可、模型版本、哈希和质量；
- LightX2V 若使用，应选明确对应 `Qwen-Image-Edit-2511-Lightning-4steps` 的权重，不能把旧版通用 Qwen-Image Lightning 名称混用。

## 三、修正后的选择逻辑

1. **默认生产**：继续采用已配置、可追踪条款的云端指令式编辑 + 多参考图；每个供应商仍单独记录输入数据、输出权利、价格和 AI 标识要求。
2. **本地高质量候选**：Qwen-Image-Edit-2511 官方链。许可证相对清晰，但 20B BF16 与当前 8GB 显卡不匹配，不能跳过资源验证。
3. **本地 8GB 候选**：FLUX.2 `[klein]` 4B 官方称约 8GB VRAM 且为 Apache-2.0，可进入后续质量 A/B；它不是 FLUX.2 `[dev]`。
4. **研究候选**：通用非 FaceID IP-Adapter。只有底模、OpenCLIP、适配器权重、参考图和具体节点全部通过时才进入商业评估。
5. **当前商业排除**：InstantID、IP-Adapter-FaceID、标准 PuLID、免费 FLUX.2 `[dev]` 本地运行。分别因 checkpoint/InsightFace 依赖或权重运行许可不闭环，而非简单按更新时间淘汰。
