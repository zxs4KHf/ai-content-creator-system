# 调研：分镜、运镜、中间关键姿态与图生视频方法论

> 调研日期：2026-07-28
> 目的：把“让静态图动起来”改造成可规划、可降级、可复盘的镜头生产流程，并嵌入本仓库 G1/G2/G3。
> 证据口径：`[VERIFIED]` 表示由论文、模型/工具官方文档或官方创作者资料直接支持；`[INFERRED]` 表示结合这些事实为本项目制定的工作假设，必须靠发布数据继续校准。

## 一、结论先行

1. **[VERIFIED] 图生视频的图和文分工不同。** 输入图负责构图、主体、光线和风格，提示词应主要描述主体动作、环境运动、摄影机运动、方向、速度和时间顺序；模糊手脸等输入缺陷会在视频里被放大。来源：[Runway Image to Video Prompting Guide](https://help.runwayml.com/hc/en-us/articles/48324313115155-Image-to-Video-Prompting-Guide)。
2. **[VERIFIED] 主体运动和摄影机运动是两类控制信号。** MotionCtrl 将二者分别建模并独立控制；CameraCtrl 进一步用相机位姿轨迹控制视点。这意味着镜头表不能只写一个含混的“动效”，必须拆成 `SUBJECT` 与 `CAMERA` 两栏。来源：[MotionCtrl 论文](https://arxiv.org/abs/2312.03641)、[CameraCtrl 论文](https://arxiv.org/abs/2404.02101)。
3. **[VERIFIED] 起止帧是真正的生成约束，不等于提示词里的文字声明。** Adobe Firefly 和 Veo 均提供首尾帧能力；Adobe 明确将二者称为固定引导点。只有在模型/接口真的提供末帧输入时，`END FRAME LOCK` 才是实际约束；否则一张输入图通常只是首帧。来源：[Adobe Firefly 首尾帧说明](https://helpx.adobe.com/uk/firefly/web/work-with-audio-and-video/work-with-video/generate-videos-using-images.html)、[Veo 首尾帧文档](https://docs.cloud.google.com/vertex-ai/generative-ai/docs/video/generate-videos-from-first-and-last-frames)。
4. **[VERIFIED] 两个端点不能自动保证中间过程合理。** 关键帧插值本身是专门研究任务，ICLR 2025 的 Generative Inbetweening 甚至要结合正向与反向估计来生成两帧之间的连贯运动；现有 I2V 的主要难点仍包括主体、背景、风格和叙事推进的一致性。来源：[Generative Inbetweening](https://proceedings.iclr.cc/paper_files/paper/2025/hash/4bbdef62653d8088717640e7660a1ebb-Abstract-Conference.html)、[ConsistI2V](https://arxiv.org/abs/2402.04324)。
5. **[INFERRED] 本项目的默认策略应是“静态动画样片先行，少数英雄镜升级”。** 先用确定性 Ken Burns 做完整可审片版，再只升级真正需要关节动作、接触、空间揭示或情绪转折的 2–3 镜；失败时可以无损回退静帧，而不是让全片质量取决于随机生成。
6. **[INFERRED] “中帧倒推”更准确的名称应是“目标状态倒推 + 必要时插入中间关键姿态”。** 中间关键姿态不是机械放在 50% 时间点，而应放在动作状态发生改变的位置，例如手即将接触书、人物重心完成转移、门刚越过遮挡边界。

## 二、从旁白节拍拆静态分镜

### 2.1 先拆“信息状态”，再算镜头数

**[VERIFIED]** YouTube 官方对 Shorts 创作者的访谈强调首秒钩子，以及用一个个能独立成立的短“moment/bit”组织短内容；Adobe 的连续性剪辑指导则要求镜头按剧本或自然可信的动作推进，并多次回放、删减或重排以收紧意图。来源：[YouTube Shorts deep dive](https://blog.youtube/creator-and-artist-stories/youtube-shorts-deep-dive/)、[Adobe：arrange clips into sequences](https://helpx.adobe.com/sk/premiere-pro/how-to/arranging-clips-to-sequence.html)。

**[INFERRED] 本项目拆镜步骤：**

1. 把最终旁白按“观众此刻新知道了什么”切成语义节拍，不按逗号机械切。
2. 给每个节拍标功能：`HOOK 钩子 / SETUP 建立 / ESCALATE 加压 / TURN 转折 / PAYOFF 回收 / ECHO 余韵`。
3. 每个节拍只回答一个视觉问题，例如“谁来了”“他作何选择”“这件事留下了什么”。
4. 遇到下列任一条件就拆镜：地点/时间变化；叙事主体变化；情绪极性变化；一个画面要承担两个独立动作；出现必须被看清的关键物；动作中发生遮挡、接触或重心变化。
5. 如果相邻两镜承担同一功能、构图和信息都没有变化，就合并；如果旁白已经进入下一信息状态但画面仍停留，就拆分或插入反应镜/物件镜。
6. 时轴以最终旁白的真实时间戳为底，先做静态 animatic，再决定是否升级运动；不要先平均分配图片时长再强迫旁白适配。

### 2.2 节奏不是“每 N 秒一切”的固定规则

**[INFERRED]** 不设全项目统一的 3 秒、5 秒或 6 秒硬阈值。采用以下可测规则：

- 开头视觉承诺必须与钩子同时出现，不能先放片头或无关氛围镜。
- 一个镜头的最短必要时长 = 观众辨认主体 + 读完必要字幕 + 接收该镜新信息所需时间。
- 只有当“信息状态、构图重心或情绪”至少一项变化时才切；用无意义切镜追求热闹会破坏叙事。
- 初始 animatic 记录每镜时长，并计算本条的中位数；单镜若明显长于相邻镜，必须注明它为何需要停留，或拆成建立镜/动作镜/反应镜。
- 发布后用留存曲线校准节拍。YouTube 官方创作者案例也把中途流失视为重新检查剪切、缩放和总时长的信号，但同时提醒不能只为指标机械化内容。来源：[YouTube 官方创作者案例](https://blog.youtube/creator-and-artist-stories/how-sydney-morgan-creates-the-smoothest-makeup-transformations/)。

## 三、镜头规格：先锁意图，再锁帧

每镜生成前都应有以下“一镜一卡”；缺任一核心字段，不进入视频生成：

| 字段 | 要回答的问题 | 例子 |
|---|---|---|
| `INTENT` | 观众看完这一镜，认知/情绪发生什么变化？ | 从“图书馆无用”转为“林伯仍选择留下” |
| `START_FRAME` | 镜头开始时可见的稳定状态是什么？ | 终端在前景，林伯低头阅读 |
| `END_FRAME` | 最后 0.5–1 秒最值得记住的状态是什么？ | 林伯完成回复，手停在桌面 |
| `KEY_POSE` | 是否存在必须经过的状态变化点？ | 手指落在确认键前一刻 |
| `SUBJECT` | 谁因为什么，按什么顺序动？ | 建议出现→眼睛移动→抬手→按键→手停 |
| `ENVIRONMENT` | 哪些环境元素微动，哪些必须锁死？ | 光尘微动；书架、字数、门的位置锁死 |
| `CAMERA` | 起点、路径、目标、速度曲线、停点？ | 终端侧后方→直线轻推→双人中近景→减速停住 |
| `CONTINUITY` | 与前后镜必须延续什么？ | 人物朝向、视线、手持物、门轴方向、光源方向 |
| `METHOD` | Ken Burns / I2V / 首尾帧 / V2V / 硬切？ | 首尾帧 I2V；失败回退轻推近 |
| `ACCEPTANCE` | 哪些条件一票否决？ | 手指不增减、屏幕不变字、无自动切镜 |

### 3.1 目标状态倒推法

**[INFERRED] 推荐顺序：**

1. **先写意图**：没有叙事作用的运动删除。
2. **锁结束状态 `F1`**：这是该镜的视觉句号，应能作为单张图表达主要信息。
3. **倒推开始状态 `F0`**：必须与 `F1` 属于同一空间、同一动作因果链，且与上一镜连续。
4. **判断是否需要关键姿态 `K`**：只要存在接触建立/解除、明显遮挡、重心转移、方向反转、身份易漂移或较大视角变化，就设计 `K`。
5. **把复杂镜拆段**：`F0 → K` 与 `K → F1` 分别生成，K 作为共享边界帧；剪辑时在动作最清楚处接合。
6. **再写摄影机**：摄影机的任务是揭示/强调意图，不得代替缺失的主体动作逻辑。

**关键纠偏：** 当前常见写法“使用 `shot_XX.png` 作为最终稳定构图”只有在该图片真的传入 `lastFrame`/末帧槽时才成立。若工具把图片作为普通 I2V 输入，它通常会被当作首帧；此时应另做开始帧，或明确选择支持首尾帧的路径，不能靠提示词假装末帧已锁定。

### 3.2 动作因果链

**[VERIFIED]** Runway 官方支持用自然语言或粗时间戳按 `X → Y → Z` 描述事件顺序，并提醒复杂序列要匹配足够时长。来源：[Runway sequential prompting](https://help.runwayml.com/hc/en-us/articles/48324313115155-Image-to-Video-Prompting-Guide)。

**[INFERRED] 人物动作统一写成五段：**

`触发 TRIGGER → 感知 PERCEIVE → 预备 PREPARE → 主动作 EXECUTE → 落稳 SETTLE`

例如：`门外雷声 → 眼睛先转向门口 → 头肩跟随 → 脚步调整重心并回望 → 双脚站稳、呼吸微动`。

执行约束：

- 一个短镜只保留一个主要动作目标；多个动词必须服务于同一因果链。
- 手持物交接、开门、落座等接触动作必须有 `接触前 / 接触成立 / 接触后` 三态，必要时将“接触成立”设为 K。
- 主动作与强运镜不要同时争抢注意力；主体动作强时，摄影机降级为锁机或轻跟随。
- 最后预留稳定区用于读表情、字幕和接切。当前仓库可先以末段约 15%–20% 为实验值，而非通用真理。

## 四、摄影机路径与运动幅度

### 4.1 用正确术语，避免模型误解

**[VERIFIED]** Runway 官方区分：`pan/tilt` 是固定点旋转，`dolly` 是摄影机实体前后移动，`tracking` 是跟随主体，`orbit/arc` 是绕主体的圆形/弧形路径，`zoom` 是改变焦距；这些效果不能混写成一个“拉近”。来源：[Runway Camera Terms](https://help.runwayml.com/hc/en-us/articles/46749315925395-Camera-Terms-Prompts-Examples)。

**[INFERRED] CAMERA 字段固定写六项：**

`起点景别与方位 → 路径类型与方向 → 是否跟随主体 → 目标景别与重心 → 速度曲线 → 落稳位置`

示例：`眼平中景、人物右后侧 → dolly in 直线轻推 → 不跟随手部 → 停在人物与终端双重构图 → 前缓后减速 → 末段锁机`。

不要写成“无人机穿过书架、旋转 180°、快速推近、再环绕人物并拉焦”这类运动堆叠。它既难验证，也会把相机路径、焦距、主体动作和场景重建混成一次高风险生成。

### 4.2 每镜只有一个“强运动通道”

**[VERIFIED]** MotionCtrl 的研究前提就是主体运动与相机运动需要区分；Luma 官方也指出过强动态、剧烈抖动和混乱摄影机会降低一致性与跟踪能力，造成变形和细节损失。来源：[MotionCtrl](https://arxiv.org/abs/2312.03641)、[Luma Modify Video FAQ](https://lumalabs.ai/learning-hub/modify-video-dream-machine)。

**[INFERRED] 为每镜分别给三条运动通道标 `0 静止 / 1 微 / 2 中 / 3 强`：**

- `S`：主体动作强度
- `C`：摄影机运动强度
- `E`：环境运动强度

起步约束：最多一条为 `3`；若 `S=3`，则 `C≤1`；若 `C=3`，主体应以静态姿态或单一微动作承接。该约束不是模型极限，而是低成本生产线的稳定性预算。

确定性 Ken Burns 另记录可复现参数，而不是“轻微”二字：

- `scale_start / scale_end`
- `x_start / y_start / x_end / y_end`（归一化画幅坐标）
- `ease`（默认 smoothstep）
- `settle_ratio`（初始实验值 0.15–0.20）

本项目可先用 `3%–6%` 缩放变化作为微运动起点；若主体脸、手或字幕安全区明显漂移，则继续减小。这是待数据/人工观感校准的项目参数，不是行业标准。

## 五、方法选择与降级路线

| 方法 | 何时首选 | 不适合 | 失败后怎么办 |
|---|---|---|---|
| 静帧/硬切 | 信息本身强；构图变化已足够；必须百分百保身份/文字 | 需要看清连续动作 | 加局部环境音、剪切或下一层 Ken Burns |
| Ken Burns | 旁白驱动、环境/物件镜、情绪停留、低成本首版 | 递物、转身、开门等关节/接触动作 | 减幅、换移动方向或直接静帧 |
| 单首帧 I2V | 有机微动作、光影/雨/尘、简单表情；输入图就是合理起点 | 必须精确落到指定结尾、复杂接触 | 简化为一个主体动作；清理输入运动暗示；降级 Ken Burns |
| 首尾帧/关键帧 | 必须从 A 落到 B，且两端人物、空间、道具可对应 | 两帧差异过大、跨地点/换人/物件凭空变化 | 插入 K 并拆两段；仍失败则硬切 |
| V2V | 动作节奏、肢体表演或摄影机路线比画风更重要；可先拍/做预演 | 没有可靠动作底片、原片极度抖动 | 稳定/简化底片，降低修改强度，或退回 I2V |

**[VERIFIED]** Luma 官方描述 V2V/Modify 可保留输入视频的动作与摄影机动态，并明确提示极端运动会带来一致性风险；Adobe 也支持用短视频作为摄影机运动参考。来源：[Luma Modify Video](https://lumalabs.ai/learning-hub/modify-video-dream-machine)、[Adobe motion reference](https://helpx.adobe.com/uk/firefly/web/work-with-audio-and-video/work-with-video/match-camera-motion-to-reference-video.html)。

**[VERIFIED]** 目前 Google 官方文档把 Gemini Omni Flash 作为默认快速、多输入、可多轮编辑的视频模型，把 Veo 3.1 用于末帧控制、延长等特定能力；产品能力与价格会变化，调用前仍需重新查官方文档。来源：[Gemini API Video Generation](https://ai.google.dev/gemini-api/docs/video)。

## 六、连续性账本

**[VERIFIED]** Adobe 的连续性剪辑资料明确要求匹配人物视线，避免让观众失去方向。来源：[Adobe continuity editing guidance](https://helpx.adobe.com/sk/premiere-pro/how-to/arranging-clips-to-sequence.html)。

**[INFERRED] 每个场景建立连续性账本，至少记录：**

- `SCREEN_DIRECTION`：人物面朝左/右，进出画方向；
- `EYELINE`：视线对象及其屏幕位置；
- `HAND/PROP`：道具在哪只手、开合/朝向/数量；
- `POSITION`：人物相对位置与前后景遮挡关系；
- `LIGHT`：主光方向、昼夜、窗外天气；
- `WARDROBE/IDENTITY`：服装、发型、年龄、识别特征；
- `CAMERA_SIDE`：同一对话是否越过人物关系轴；
- `BOUNDARY_FRAME`：上一镜末帧与下一镜首帧能否自然接上。

最便宜的连续性策略不是在提示词里堆更多形容词，而是减少同一镜需要重建的不可见空间；大幅绕拍会暴露单张图没有提供的背面信息，角色与背景更容易漂移。

## 七、QA：逐镜验收而非“看起来挺顺”

### 7.1 必检采样点

**[INFERRED]** 每条生成镜至少检查 `0% / 25% / 50% / 75% / 100%` 五帧，并额外检查所有接触、遮挡和方向反转时刻。终审必须同时看：静音画面、正常声画、0.5 倍速、逐帧关键点，以及相邻镜边界。

### 7.2 失败模式与修复顺序

| 失败 | 判据 | 优先修复 |
|---|---|---|
| 身份/服装漂移 | 脸、年龄、发型、颜色、独特标志变化 | 缩小动作/视角；更干净首帧；改用 V2V 或静帧 |
| 解剖/接触错误 | 手指数、关节、书/门穿模，抓取前后不成立 | 设 K；拆成接触前后两段；把接触藏在切点 |
| 道具/背景拓扑漂移 | 书本数量、门窗、文字、架构增减或融化 | 把文字后期叠加；降低相机幅度；锁机 |
| 运动方向矛盾 | 输入图的运动模糊/姿态指向 A，提示词要求 B | 先修首帧，移除矛盾的模糊、尘土、方向线 |
| 自动切镜/瞬移 | 单次生成内突然换角度、场景或主体 | 延长时长或减少事件；明确 continuous seamless shot；仍失败则拆镜 |
| 摄影机术语混乱 | zoom/dolly/pan 同时出现且效果不可预测 | 只留一个主路径，明确起终点与速度 |
| 画面抖动/呼吸 | 本应锁机却随机缩放、背景摆动 | 指定 locked-off/minimal motion，后期稳定；失败即退 Ken Burns |
| 节奏“滑屏”感 | 每镜都同向同速推近，无叙事层级 | 按意图交替静、推、拉、横移；让强运动只出现在转折/揭示 |
| 末尾硬停 | 动作未完成即切，或突然冻结 | 提前完成主动作，末段减速；在稳定姿态处切 |
| 相邻镜跳轴 | 视线、左右位置、道具手、光向突然反转 | 对照连续性账本重做首/末帧或插入中性建立镜 |

**[VERIFIED]** Runway 官方说明：输入图中的模糊、动作姿态和方向线会暗示运动，与提示词矛盾时更难得到预期结果；无意切镜可先增加时长、移除暗示切镜的措辞并指定连续镜头；完全锁定摄影机也不一定一次成功，可能仍需后期稳定。来源：[Runway I2V FAQ](https://help.runwayml.com/hc/en-us/articles/48324313115155-Image-to-Video-Prompting-Guide)。

**[INFERRED] 固定修复阶梯：**

`修首帧缺陷 → 简化提示词 → 删除一个运动通道 → 降低幅度 → 插入 K/拆镜 → 换成 V2V → 回退 Ken Burns/静帧`

同一配置连续失败 2 次，不再盲抽；先改变一个可归因变量并记录结果。

## 八、嵌入本仓库 G1/G2/G3

### G1 选题门：只增加“可视化可行性”，不评动画细节

**[INFERRED] 建议在选题方案附 4 项：**

- 3 个最重要视觉 moment；
- 是否依赖固定角色/复杂接触/大视角运动；
- 动画成本层级 `A 静态/Ken Burns / B 少量 I2V / C 关键帧或 V2V`；
- 最大失败回退方案，以及回退后是否仍值得做。

G1 的目标是避免选中“只有昂贵复杂动画才能成立”的题，不要求用户逐镜审批。

### G2 脚本门：脚本、节拍、英雄镜同时冻结

**[INFERRED] G2 前由 AI 自检：**

1. 把旁白写入 `beat_id + role + narration + visual_question` 节拍表；
2. 生成一镜一卡的 10 个字段；
3. 标出最多 2–3 个英雄镜和每镜升级理由；
4. 建立角色锁与连续性账本；
5. 先产低清静态 animatic，用真实旁白时长检查节奏；
6. G2 通过即冻结叙事意图、台词和英雄镜；后续技术重试不得偷偷改剧情。

### G2 → G3：先确定性全片，后风险升级

**[INFERRED] 推荐流水线：**

`真实旁白时轴 → 静态分镜 animatic → 节奏 QA → Ken Burns 全片 → 英雄镜逐镜生成 → 五点/接触帧 QA → 替换合格镜 → 声画 QA → G3`

每个英雄镜保留：输入帧、提示词、模型/版本、参数/seed（若支持）、输出、失败原因、选择结论。没有通过验收的动态镜不得因为“已经花钱”而进入成片。

### G3 成片门：把运动质量变成明确问题

**[INFERRED] G3 自检新增四问：**

- 运动是否强化了该镜 `INTENT`，还是只增加热闹？
- 任一帧是否出现身份、手部、道具、背景或文字错误？
- 相邻镜的视线、方向、动作和光线是否连续？
- 关掉声音能否理解动作，闭眼只听声音又是否节奏自然？

G3 仍由人作最终成片裁决；模型重试、逐镜降级和技术 QA 属于 G2→G3 内部流程，不新增打扰用户的审批门。

## 九、建议的最小落地改造（后续实现清单）

1. 在分镜模板加入 `beat_role / intent / F0 / K / F1 / subject / environment / camera / continuity / method / acceptance`。
2. 把运动计划 JSON 从单一 `mode + amount` 扩展为 `subject_motion / camera_motion / environment_motion / ease / settle_ratio / fallback`，Ken Burns 保留明确坐标参数。
3. 增加 `continuity_ledger.json` 或同等 Markdown 表，角色、道具、屏幕方向由前一镜自动继承，只有明确剧情原因才允许改。
4. 给视频流程增加“英雄镜预算”：默认全片最多 2–3 镜进入付费/随机视频生成，其余确定性完成。
5. 增加生成记录表；每次只改变一个变量，连续两次失败触发修复阶梯而非继续抽卡。
6. 增加五帧联络表与接触帧检查；最终联络表不能只抽每镜一张代表帧，否则会漏掉中段变形。
7. 修订现有 `END FRAME LOCK` 骨架：必须记录 `endpoint_binding = actual_last_frame | prompt_only`；`prompt_only` 不得标记为已锁定。
8. 第一轮 A/B 验证只选同一成片的 3 个英雄镜：一个人物回望、一个递物接触、一个开门+揭示；分别验证单首帧、首尾帧/中间姿态、V2V 或确定性回退，记录成本、成功率和主观收益。

## 十、研究边界

- **[VERIFIED]** 文中产品能力来自 2026-07-28 可访问的官方文档；模型、价格、免费额度和接口会变化，采购或调用时必须重新核验。
- **[INFERRED]** `3%–6%` Ken Burns、`15%–20%` 末段稳定区、全片 `2–3` 个英雄镜、同配置失败 `2` 次即停，均是本项目的低成本起始参数，不应包装成普遍规律。
- 本文没有证明某一家模型在本项目角色画风上最好；必须用同一镜头、同一验收表和实际成本做小样对比后再选型。
- 本文只处理镜头设计与生成链路，不替代版权、肖像、平台 AI 标识及发布前人工确认流程。
