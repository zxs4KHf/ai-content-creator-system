# 调研：高质量本地与开源 TTS（2026-07-28）

- 目标机器：Windows 11，RTX 3060 Ti 8GB，约 64GB 内存。
- 目标声音：自然、耐听、有表演感的年轻女声；中文故事旁白为主，英文整句和中英混读不能明显降级。
- 目标质量：尽量接近 MiniMax 等商业服务的成片水平，同时把持续成本压到最低。
- 证据边界：只采用项目官方仓库、官方模型卡、论文和许可证。本文没有下载权重、安装环境或试听模型。
- 标签：`[DOCUMENTED]` 为一手资料明示；`[VERIFIED]` 为本机/仓库已验证；`[INFERRED]` 为由规格推得、仍需本机实测；`[CONFLICT]` 为一手资料之间不一致；`[UNKNOWN]` 为官方未给出。

> 模型许可证、代码许可证、训练数据权利、参考声音权利和最终输出的商用权是不同问题。Apache/MIT 不等于可以克隆任意真人。不得下载或克隆目标 UP 主、演员、主播或普通人的声音；只能学习停顿、节拍、能量、重音和情绪曲线等抽象表演变量。

## 结论先行

1. **此前四个试听只是 Edge 在线系统音色基线，不代表当前开源大模型的上限。** 要判断本地路线，至少要听到 `Qwen3-TTS 1.7B`、`VoxCPM2` 和 `CosyVoice3` 的同稿盲测，不能拿 Edge 样本直接否定本地 TTS。
2. **第一优先不是 Qwen3-TTS 0.6B，而是 1.7B。** `[DOCUMENTED]` 只有 1.7B CustomVoice 明确提供自然语言指令控制；0.6B CustomVoice 有同样的 9 个内置音色，但官方能力表没有指令控制。1.7B 还提供 VoiceDesign，可先设计原创女声，再交给 1.7B Base 固化为可复用克隆提示。
3. **最低成本且最有希望的首轮是三引擎四候选：**
   - `Qwen3-TTS-12Hz-1.7B-CustomVoice / Serena`：温暖、温柔的中文年轻女声；
   - `Qwen3-TTS-12Hz-1.7B-CustomVoice / Vivian`：明亮、略有锋利感的中文年轻女声；
   - `Qwen3-TTS-12Hz-1.7B-VoiceDesign -> 1.7B-Base`：设计原创双语女声并固化；
   - `VoxCPM2 Voice Design / Controllable Clone`：原创女声设计、情绪/语速控制和 48kHz 输出。
4. **CosyVoice3 是第三个必须测的渲染器。** 它只有 0.5B，但官方同测试表中内容一致性和说话人相似度已接近封闭模型；它支持 9 种语言、中文方言、跨语种克隆、情绪/速度/音量指令和发音修补。缺点是官方安装链明显偏 Linux，Windows 应按 WSL2 路线规划。
5. **VoxCPM2 正好卡在本机物理上限。** 官方标注约 8GB VRAM；3060 Ti 上必须单模型、batch=1、关闭 denoiser 起步，并预留 OOM 降级到 VoxCPM1.5（约 6GB）。它不是“不可能”，但不能把一次勉强生成当成可生产。
6. **MOSS-TTS v1.5 的 8B 量化版确实能塞进 8GB，但不是第一轮。** 官方低显存方案要 GGUF + llama.cpp + ONNX/TensorRT 分阶段装卸，模型与音频 tokenizer 的磁盘占用和 Windows 工程成本都高；适合后续验证长文本、显式停顿和时长控制，不适合最快得到第一条好女声。
7. **IndexTTS2 情绪能力很强，但先卡许可证和长批稳定性。** 官方 README 要求商业合作联系团队，而当前模型许可证又在一定规模阈值下授予广泛使用权，存在解释冲突；精确时长控制在公开版最初也注明未启用。未书面澄清前只做内部评测，不进入变现内容。
8. **GPT-SoVITS v4 更像“账号专属声音工作室”，不是最快的通用旁白升级。** 它原生支持 Windows、少样本微调和中英混合，适合未来用本人或签约配音员数据训练长期资产；没有合法、干净、稳定的女声数据时，不应靠抓取博主音频启动。

## 逐模型结论

### 1. Qwen3-TTS 0.6B / 1.7B

**一手事实**

- `[DOCUMENTED]` 代码和官方模型卡标注 Apache-2.0；覆盖中文、英文等 10 种语言，支持流式生成。
- `[DOCUMENTED]` 1.7B 有 `CustomVoice`、`VoiceDesign`、`Base` 三条路线；0.6B 有 `CustomVoice` 和 `Base`。
- `[DOCUMENTED]` 1.7B CustomVoice 支持指令控制，0.6B CustomVoice 的官方能力表没有该能力。
- `[DOCUMENTED]` 中文女声中，`Serena` 是温暖温柔的年轻女声，`Vivian` 是明亮、略带锋利感的年轻女声。官方建议优先使用音色的母语；虽然音色能说全部支持语言，但不能据此假设中文原生女声的英文一定无口音。
- `[DOCUMENTED]` Base 可用约 3 秒参考音频快速克隆；官方给出了“VoiceDesign 先生成短参考，再由 Base 建立可复用 clone prompt”的完整工作流。
- `[DOCUMENTED]` 官方同一 Seed-TTS 测试表中，12Hz 1.7B Base 的中/英文 WER 为 0.77/1.24，MiniMax-Speech 为 0.83/1.65。该结果只证明内容正确率有竞争力，不能证明听感、音色和表演已胜过 MiniMax。
- `[DOCUMENTED]` 0.6B CustomVoice 官方模型仓库约 2.5GB；1.7B CustomVoice 仓库约 4.52GB，其中主权重约 3.83GB。官方未公布最低显存。

**本机判断**

- `[INFERRED]` 1.7B 单模型 BF16 权重约 3.83GB，配合 batch=1、短分段和 SDPA/FlashAttention，有机会在 8GB 运行；但激活、音频 tokenizer 和 CUDA 上下文会吃掉余量，必须实测峰值显存。
- 原生 Windows 可先尝试不安装 FlashAttention；若依赖失败或峰值显存明显偏高，转 WSL2。官方只给通用 Conda/PyPI 路线，没有承诺 Windows 原生支持。
- `VoiceDesign -> Base` 不能同时把两套 1.7B 留在显存。应分成两个进程：进程 A 只设计并保存参考 WAV；退出后进程 B 加载 Base，创建并保存声线 manifest。

**女声与英文策略**

1. 快速候选：Serena 与 Vivian 各用 3 个导演指令、3 个 seed。
2. 更高上限：VoiceDesign 生成“原创、非真人映射”的中低音区温暖女声，再用 Base 固化。
3. 英文必须单列测试：英文整句、缩写、数字、品牌名，以及一句内中文到英文再回中文。若 Serena/Vivian 英文口音不达标，使用双语 VoiceDesign/Base 声线，不用后期变调伪装。

**时间戳**

- `[UNKNOWN]` 官方本地生成接口没有承诺词级时间戳。输出后继续用 faster-whisper/stable-ts 对齐并标记为后对齐，不得按字数均分时间。

来源：[官方仓库与能力表](https://github.com/QwenLM/Qwen3-TTS)、[0.6B CustomVoice 模型卡与文件](https://huggingface.co/Qwen/Qwen3-TTS-12Hz-0.6B-CustomVoice/tree/main)、[1.7B CustomVoice 模型卡与文件](https://huggingface.co/Qwen/Qwen3-TTS-12Hz-1.7B-CustomVoice/tree/main)、[Apache-2.0](https://github.com/QwenLM/Qwen3-TTS/blob/main/LICENSE)

### 2. VoxCPM2 / VoxCPM1.5

**一手事实**

- `[DOCUMENTED]` VoxCPM2 为 2B 参数、30 语言、48kHz 输出，提供无参考 Voice Design、可控克隆、带转录的高保真 continuation clone、流式和批量接口。
- `[DOCUMENTED]` Voice Design 可直接写“年轻女性、温暖温柔、略带笑意”等描述；克隆后仍可用文本控制语速、情绪和风格。
- `[DOCUMENTED]` 官方显存表：VoxCPM2 约 8GB、VoxCPM1.5 约 6GB、旧 0.5B 约 5GB；官方模型仓库约 4.96GB。
- `[DOCUMENTED]` 可选 `voxcpm[timestamps]` 用 stable-ts 后对齐词级时间戳；中文字符级时间由词对齐派生，官方明确为 best-effort，不是生成模型原生时间码。
- `[DOCUMENTED]` 代码和权重 Apache-2.0，官方明确可免费商用；同时禁止冒充、欺诈和虚假信息，要求清楚标记 AI 内容。
- `[DOCUMENTED]` 官方列出的局限包括：Voice Design/风格控制会随运行波动，建议生成 1–3 次；超长或高情绪输入偶发不稳定。

**本机判断**

- 3060 Ti 8GB 是硬边界。首测必须：单模型、batch=1、关闭其他 GPU 应用、`load_denoiser=False`、短段生成、记录峰值显存和 RTF。
- 若任何连续稳定性测试出现 OOM，不做系统 swap 或驱动级取巧，直接降 VoxCPM1.5。稳定生产比偶尔跑通更重要。
- 官方 Python 安装未承诺 Windows；可先原生试 `pip install voxcpm`，失败即转 WSL2。官方 llama.cpp-omni 还提供 CPU/Metal/CUDA/Vulkan 路线，但文档中的 CUDA 构建示例偏 Linux，首轮不把 C++ 移植纳入关键路径。

**女声策略**

- 先只用 Voice Design 生成 12 个原创女声候选：`3 个声音人格 × 2 个情绪强度 × 2 个 seed`。
- 入围声音保存设计文本、seed、模型 revision 和 WAV 哈希，再用 Controllable Clone 固化；不把目标 UP 的公开音频作为参考。
- VoxCPM2 同时支持中文和英文，但官方也提示语言表现受训练数据量影响，因此仍需独立英文门。

来源：[官方仓库、显存表和时间戳用法](https://github.com/OpenBMB/VoxCPM)、[官方模型卡与文件](https://huggingface.co/openbmb/VoxCPM2/tree/main)、[Apache-2.0](https://github.com/OpenBMB/VoxCPM/blob/main/LICENSE)

### 3. CosyVoice3 0.5B-2512

**一手事实**

- `[DOCUMENTED]` Apache-2.0；覆盖中英等 9 种语言和 18+ 中文方言/口音，支持多语种/跨语种零样本克隆。
- `[DOCUMENTED]` 支持语言、方言、情绪、速度、音量指令，以及中文拼音和英文 CMU 音素的发音修补；这对专名和英文稳定性很有价值。
- `[DOCUMENTED]` 官方模型仓库完整快照约 9.75GB，包含普通/RL LLM、Torch/ONNX 等重复或替代运行文件；磁盘体积不等于 0.5B 主模型的峰值显存。
- `[DOCUMENTED]` 官方同表中，0.5B-2512_RL 的中文 CER 为 0.81、英文 WER 为 1.68；表内 MiniMax-Speech 为 0.83/1.65。两者内容错误率接近，但相似度、自然度、音色偏好仍需盲听。
- `[UNKNOWN]` 官方没有给出 8GB 峰值显存，也没有承诺本地词级时间戳。

**本机判断**

- `[INFERRED]` 0.5B 主模型在 8GB 上应比 VoxCPM2 宽松，但 flow、tokenizer、vocoder 和运行时总峰值必须实测。
- 官方可选 `ttsfrd` 只给 Linux x86_64 wheel，部署/服务示例也以 Docker/Linux 为主；Windows 应优先 WSL2。若不用 `ttsfrd`，官方会回退 WeTextProcessing。
- 它没有现成的 Serena/Vivian 式中文女声清单；需要合法参考声。最佳低成本做法是用 Qwen VoiceDesign 或 VoxCPM2 Voice Design 创建原创参考，再由 CosyVoice3 渲染同一声线并做 A/B。

来源：[官方仓库、指标与安装](https://github.com/FunAudioLLM/CosyVoice)、[官方模型文件](https://huggingface.co/FunAudioLLM/Fun-CosyVoice3-0.5B-2512/tree/main)、[Apache-2.0](https://github.com/FunAudioLLM/CosyVoice/blob/main/LICENSE)

### 4. IndexTTS2

**一手事实**

- `[DOCUMENTED]` 中英模型，支持独立音色参考和情绪参考、8 维情绪向量、情绪文本描述和中文拼音控制；官方推荐情绪文本模式将强度控制在约 0.6 或更低，以保持自然。
- `[DOCUMENTED]` 当前官方安装明确支持 Windows，但建议使用 `uv`；Windows 的 DeepSpeed 和 FlashAttention/Triton 需要特殊处理，可只用 `--fp16` 降显存。
- `[DOCUMENTED]` 官方权重仓库约 5.9GB，运行时还会下载少量辅助模型；官方没有给最低显存。
- `[CONFLICT]` README 写“商业使用与合作请联系团队”；当前 bilibili 模型协议又授予全球、免版税的有限使用权，只对月活超过 1 亿或年收入超过 10 亿元的主体要求单独授权。协议还把模型输出广泛定义为衍生作品，并附带下游义务。正式变现前应取得书面解释，不靠本文做法律判断。

**结论**

- 适合做“情绪上限挑战”，不适合在许可证和 100 段连续稳定性未通过前成为默认引擎。
- 本地时间戳仍需后对齐。精确时长接口未确认启用前，不得据此省略字幕/口型 QA。

**一手事实**

- `[DOCUMENTED]` MOSS-TTS v1.5 为 8B，支持 31 种语言、长文本、零样本克隆、code-switch、拼音/IPA、token 级时长和 `[pause X.Ys]` 显式停顿；模型家族为 Apache-2.0。

- MOSS 的优势是长文控制，不是最快找到好听女声。把它放在第二阶段，与首轮胜者对比 3–5 分钟长旁白稳定性。

## 低成本“原创女声工厂”方案

商业 API 好听往往不只是模型更大，而是声线资产、导演提示、分段生成、候选挑选和后期共同作用。最低成本接近该水平，应把流程拆成“设计声线”和“表演渲染”两层。

### A. 声线设计层（一次性成本）

固定三个原创方向，不使用真人姓名或“像某某”的描述：

1. **S1 温暖故事声**：年轻成年女声，中低音区，温暖克制，略带气声但咬字清楚，像在安静房间里对一个人讲故事；禁止播音腔、客服腔、夸张卖萌。
2. **S2 清醒悬疑声**：年轻成年女声，音色干净，能量偏低，停顿有目的，疑问处收紧而非抬高；禁止故作深沉和句句拖尾。
3. **S3 明亮知识声**：自然、有亲和力、思路清楚，关键词轻重音明显，节奏略快但不赶；禁止广告腔和机械等时长断句。

用 Qwen VoiceDesign 和 VoxCPM2 Voice Design 各生成上述 3 种方向，每种 2 个 seed；12 个候选盲选 2 个。每个入围声音保存：

- 模型、revision、设计提示、seed；
- 参考文本和语言；
- 原始 WAV SHA-256、采样率、响度；
- `source=synthetic_voice_design`；
- 允许用途、生成日期、许可证快照；
- 明确 `real_person_reference=false`。

### B. 表演渲染层（每条内容成本）

同一声线分别交给 Qwen Base、VoxCPM2 Clone、CosyVoice3 渲染。不要一次生成 70 秒后只听整体；按语义表演块生成：

```text
VOICE_ID: S1
INTENT: 像把只告诉一个人的秘密慢慢说出来
SUBTEXT: 她知道结局，但不急着揭晓
ENERGY: 2/5 -> 3/5 -> 1/5
PACE: 自然偏慢，关键句前停 250–450ms
EMPHASIS: “最后一本”“她没有回头”
ENDING: 句尾自然落下，不拖长，不每句同一曲线
FORBID: 播音腔、广告腔、客服微笑、均匀停顿、夸张气声
```

- 每块建议 8–20 秒，边界落在情绪或信息状态变化处，不按固定字数硬切。
- 每块 2–3 个 seed，只有英雄句可多生成；普通句不无限抽卡。
- 需要大幅改变语速时重新生成，不靠超过约 ±3% 的整段拉伸修补。
- 后期只做轻量去齿、必要的 EQ/压缩、响度和 true peak 统一；不把重度降噪、混响和变调当成“自然度”。
- 英文块显式传 `language=English`；中英混读同时测自动识别和显式分块两条路线，选听感更自然且声线连续的方案。

## 统一盲测与淘汰门

### 固定测试集

每个候选用完全相同文本、未经后期的 WAV：

1. 中文温暖叙事：平静、秘密感、情绪回落；
2. 中文悬疑：从克制到紧张再释放；
3. 中文知识口播：数字、年份、专名、多音字；
4. 英文整句：自然美式或中性国际口音，不允许逐词读；
5. 中英混读：`2026 年，我们把 voice design 变成了真正可复用的账号资产。`；
6. 30–45 秒长段：检查气口、重复、漏字、尾音和音色漂移。

### 人工评分（1–5）

- 自然度 30%；
- 表演/情绪贴合 20%；
- 中文可懂度与专名 15%；
- 英文自然度与重音 15%；
- 声线一致性 10%；
- 长听耐受度 10%。

硬门：自然度、中文可懂度、英文自然度任一低于 4.0，不进入 G3 影子候选。英文只占少量内容时也不能把它并入“总体还行”掩盖。

### 工程稳定性门

- 记录冷启动、首包、总耗时、RTF、峰值 VRAM、失败原因；
- `3 种表演 × 3 seeds` 后，再连续生成 100 个 8–20 秒片段；
- 100 段不得 OOM、显存持续增长、模型崩溃、不可控重复；
- ASR CER/WER 只做错误筛查，最终逐句人工核对；
- 词时间戳统一后对齐，抽查至少 20 个边界；
- 所有参数、模型 revision、文本 hash、音频 hash 可追溯。

## 推荐的实际下载/测试顺序

这部分只定义顺序，不代表已经授权下载。

1. **Qwen3-TTS 1.7B CustomVoice**：只下这一套，先测 Serena/Vivian；若单模型仍 OOM，再测 0.6B，不反过来。
2. **VoxCPM2**：关闭 denoiser、batch=1；OOM 或连续稳定性失败即转 VoxCPM1.5。
3. **Qwen3 1.7B VoiceDesign 与 Base**：分两个独立进程，只为入围声线生成并固化参考，不常驻两模型。
4. **CosyVoice3 0.5B**：WSL2 独立环境，用入围原创参考做克隆与英文/专名对比。
5. 只有前三项仍不能达到目标时，才投入 **IndexTTS2**（先澄清许可）和 **MOSS-TTS Q4**（先核算约 12–20GB 权重与 WSL2 工程成本）。
6. **GPT-SoVITS** 等到有本人/签约女声的合法训练数据再做，不把“开源”误当成“参考音随便拿”。

## 需要更新的认知

- “本地模型弱于 MiniMax”目前是 `[UNKNOWN]`，因为本机还没有对 2026 的强本地模型做同稿试听。
- “更大一定更自然”不成立。CosyVoice3 0.5B 在官方内容一致性测试中很强；声线资产、提示、分段和挑选会显著影响最终观感。
- “英文支持”不等于“英文好听”。必须区分能读、读对、口音自然、重音自然、与中文保持同一声线五个层级。
- “48kHz”不等于真人感。采样率只决定输出带宽，不能修复错误韵律、均匀停顿和 AI 腔。
- 最低成本路线不是无限注册免费 API，而是把本地模型用于声线发现和大批量渲染，把正规低价云 API 仅用于英雄句/最终对照，并遵守额度和条款。

## 最终建议

当前应把本地默认候选从“Qwen3-TTS 0.6B”上调为 **Qwen3-TTS 1.7B CustomVoice**，同时把 **VoxCPM2** 作为原创声线设计与自然度上限候选，把 **CosyVoice3** 作为合法参考声的第三渲染器。三者通过同稿、同响度、去标识盲测后再决定默认引擎；没有盲测结果前，不声称任何本地模型已经达到或超过目标 UP/MiniMax。

若首轮只能授权一套多 GB 下载，选 **Qwen3-TTS 1.7B CustomVoice**；若能授权两套，第二套选 **VoxCPM2**。这是在当前硬件、自然女声、中英混读、许可证和工程成本之间最合理的先后顺序。
