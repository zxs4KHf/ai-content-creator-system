# 发布服务部署

> **铁律一：这些服务只在你本地 Windows 上跑。**
> 云端沙箱碰登录态 = 跨境 IP + 代理出口访问平台 = 账号风险。任何云端会话都不应该持有你的 cookie。
>
> **铁律二：发布动作必须先经人确认。** 发出去撤不回来。

---

## 信任域划分（这决定了所有部署位置）

| 环节 | 跑在哪 | 为什么 |
|---|---|---|
| 选题、脚本、分镜、生图提示词、多平台文案 | **云端会话** | 纯文本，无登录态，无 IP 要求 |
| 生图 API 调用、配音、视频合成 | 两边都行 | 只需要 API Key，不涉及平台账号 |
| **所有发布、所有平台数据抓取** | **只能本地 Windows** | 需要 cookie / 需要固定 IP 白名单 / 需要剪映客户端 |

## 一、小红书：xiaohongshu-mcp

Go 单二进制，无 Python 依赖地狱，Windows 上跑得干净。暴露 13 个标准 MCP 工具。

### 安装

到 https://github.com/xpzouying/xiaohongshu-mcp 的 Releases 下载 Windows 预编译二进制（也提供 Docker 和源码编译）。

### 登录（一次性，扫码）

```bash
# 用配套的登录二进制扫码，cookie 存在本地 cookies/ 目录
xiaohongshu-login.exe
```

### 启动服务

```bash
xiaohongshu-mcp.exe
# 默认监听 :18060，调试时加 -headless=false 可以看到浏览器
```

### 接进 Claude

```bash
claude mcp add --transport http xiaohongshu-mcp http://localhost:18060/mcp
```

或写进 MCP 配置：

```json
{
  "mcpServers": {
    "xiaohongshu-mcp": {
      "url": "http://localhost:18060/mcp",
      "description": "小红书内容发布服务 - MCP Streamable HTTP"
    }
  }
}
```

### 可用工具

`check_login_status` `get_login_qrcode` `delete_cookies` `publish_content`(图文) `publish_video`
`search_posts` `get_feed_list` `get_feed_detail` `post_comment` `reply_comment` `like_feed`
`collect_feed` `get_user_profile`

⚠️ `publish_content` 接受 HTTP/HTTPS 图片链接或本地路径；`publish_video` **只接本地文件**。

**顺带的好处**：`search_posts` / `get_feed_detail` 可以合规地做选题调研和对标账号分析，
比爬虫方案干净得多（同一个已登录浏览器上下文，不逆向签名）。

## 二、图文一稿多发：Wechatsync

Chrome MV3 扩展，一稿同步 29+ 平台（公众号、知乎、微博、头条、掘金、CSDN、B站、豆瓣、百家…）。

**它的设计原则值得记住**：复用你自己的登录态 + 调平台官方接口 + 全程本地不过第三方服务器。
相比模拟点击 DOM 的方案，**调接口稳定得多**（接口比 DOM 稳）。

### 安装

https://github.com/wechatsync/Wechatsync — Chrome 扩展。2.x 版本自带 CLI 工具 + MCP server，
兼容 Claude Code / Claude Desktop，所以 Claude 可以直接驱动，不用你写胶水。

### 定位

**图文赛道用它，视频赛道不用。** 我们的内容形态以图文为主（微故事 + 插画、知识教程），
Wechatsync 正好是图文覆盖之王。

## 三、公众号：md2wechat

markdown → 公众号排版 → 推草稿箱。48 个主题，支持 AI 配图生成。

### 安装

https://github.com/geekjourneyx/md2wechat-skill —— **它本身就是一个 Claude Code Skill**，
含 `.claude-plugin/` 和 `skills/md2wechat/`。

⚠️ **License 是 Source Available，商用需要授权。变现前先解决这件事。**

### 用法

```bash
md2wechat convert --draft article.md
```

推到草稿箱，你在后台点发布 —— **这正好是最后一道人工门**。

### 两个坑（很重要）

1. **IP 白名单**：公众号 API 要求当前 IP 必须登记在公众号后台。
   动态 IP 需要固定出口。**这条直接决定了公众号发布不可能从云端沙箱发出去。**
2. **草稿箱优先**：2025-07 之后未认证账号越来越只能走草稿箱模式，群发接口受限。
   反正我们本来就要人工终审，草稿箱模式是正解，不是妥协。

## 四、抖音 / 视频号：暂不自动化

**结论：手动发。**

理由是硬证据：浏览器自动化方案（如 social-auto-upload）依赖对抗平台风控，
天然是易碎件——该项目已衍生出多个第三方"修复版"分支（loongtrip、zydgmail、ebba 等），
这是上游跟不上平台前端改版的典型症状，其 README 也自承曾维护静默。

**不把核心链路押在易碎件上。**

AI 的责任是把物料准备到"打开发布页只需复制粘贴"的程度：
- `final.mp4` 已合成好，规格正确
- 封面图已单独出好
- 标题、文案、标签、置顶评论全部写好，无占位符

这样手动发一条不超过 2 分钟。等哪天有稳定的官方接口再自动化。

## 五、选题雷达：TrendRadar（可选，唯一能上云的）

https://github.com/sansan0/TrendRadar

**它是唯一一个可以安全放在云端跑的平台工具**——只吃公开热榜（NewsNow API + RSS），
不碰任何登录态、不爬私有接口。有原生 MCP 支持，可用 GitHub Actions 定时，零运维。

值得抄的是它的配置语法（已经吸收进 `91_知识库/K7_选题雷达源.md`）：

```
[情感故事]              ← 方括号 = 关键词分组
/深夜.*(独白|自述)/     ← 斜杠 = 正则
分手 => 亲密关系        ← => 显示别名
职场 @5                 ← @数字 = 该词最多显示 5 条
```

外加 `ai_interests.txt` 用自然语言描述兴趣、由 LLM 打标签评分。
**这套「正则硬过滤 + LLM 软打分」双层结构就是我们选题门的实现方案。**

**起号期建议：先不装。** 收集箱 + 手动看热榜 + 搜索下拉框，足够支撑前 30 条内容。

## 六、明确不用的（省下的时间比装上的价值大）

| 项目 | 为什么不用 |
|---|---|
| **MediaCrawler** | 技术最强（49.7k star），但**明确禁止商用**，且需挂登录态高频抓取。要变现就别把账号和法务风险押在选题调研上 |
| **Spider_XHS** | 硬逆向签名路线（`a1`/`websectiga`/`sec_poison_id`），迟早会碎，且禁商用。要小红书数据用 xiaohongshu-mcp 的 `search_posts` |
| **Postiz** | 30.4k star 是幻觉——**零中文平台**，一个都没有 |
| **wxauto** | 自动化的是**个人微信聊天**，和公众号发布毫无关系。常被误分类 |
| **n8n / Dify / Coze 作为运行时** | 我们已经有 Claude 做编排，再套一层只多一个要维护的中间件，且中文平台连接器基本空白。只从它们的模板里扒 prompt，不拿运行时 |

---

## 七、部署优先级建议

起号期（前 30 条）**只需要装第 1 项**：

1. ✅ **xiaohongshu-mcp** —— 小红书是我们的试错场，生产最快、验证最快，值得先自动化
2. ⏳ Wechatsync —— 等图文量上来再装
3. ⏳ md2wechat —— 等公众号开始规律更新再装（注意商用授权）
4. ❌ 抖音/视频号 —— 一直手动，直到有稳定官方接口

**不要一次全装。** 每个服务都是要维护的东西，装了不用是负债。
