# AI 自媒体系统 · 操作手册

> **这份文件是本文件夹的"操作系统"。**
> 每次开新会话，连接本文件夹后对 AI 说一句：**"按 README 的工作流继续"**，AI 读完即知道怎么干活。
>
> 版本 v2.0（2026-07-26）· 变更历史见 `93_运行记录/决策日志.md`

## 一、这套系统在做什么

搭一条 **AI 做绝大部分事、人只在三个关键节点评审** 的自媒体生产线。

```
① 想法池与调研 ─→【G1 选题门】─→ ② 内容生成 ─→【G2 脚本门】
                                                      │
   ┌──────────────────────────────────────────────────┘
   ↓
③ 素材生成 + 视频剪辑 ─→【G3 成片门】─→ ④ 全平台发布
                                              │
   ┌──────────────────────────────────────────┘
   ↓
⑤ 数据复盘 ──→ 反哺选题库权重 / 模板 / 知识库 ──↺ 回到 ①
```

**飞轮的关键在第 ⑤ 步**：每转一圈，把复盘结论写回**文件**——不是写回脑子。
`91_知识库` 和 `90_模板库` 就是这条流水线的可变部分，改它们 = 改流程。

## 二、四层结构（这是理解整个系统的关键）

| 层 | 是什么 | 目录 |
|---|---|---|
| **依据层** | 账号定位、角色资产——一切生产的前提 | `00_账号定位/` |
| **约束层** | 知识库——**AI 生成时的硬约束，不是参考读物** | `91_知识库/` |
| **能力层** | Skills（怎么做）+ 工具箱（用什么做） | `.claude/skills/`、`92_工具箱/` |
| **流转层** | 内容按状态在目录间移动 | `01_` → `02_` → `03_` → `04_` |

> **约束层是 v2.0 最重要的新增。** 以前 AI 靠"感觉"写钩子、拍脑袋定平台字数；
> 现在钩子必须从 17 种公式里选并标编号，标题字数必须对照实测规格表。
> **把判断标准从 AI 的即兴发挥变成可审计的文件。**

## 四、四个阶段与三道门

| 阶段 | 谁做 | Skill | 产出 |
|---|---|---|---|
| **① 想法池与调研** | AI 并行扫多源 | `zimeiti-radar` | 打分排序的选题 |
| **【G1 选题门】** | **你** | — | 在 Top 5 里勾选 |
| **② 内容生成** | AI | `zimeiti-script` | 方案 / 正文 / 分镜 / 生图提示词 |
| **【G2 脚本门】** | **你** | — | 圈一个钩子，通过或给意见 |
| **③ 素材生成** | AI + 你挑图 | `zimeiti-visual` | 插画 / 卡片 / 配音 |
| **③ 视频剪辑** | AI | `zimeiti-video` | 竖版成片 / 剪映草稿 |
| **【G3 成片门】** | **你** | — | 终审，能不能发 |
| **④ 全平台发布** | AI 备料 + 半自动发 | `zimeiti-publish` | 六平台物料 + 发布 |
| **⑤ 数据复盘** | 你贴数据 + AI 分析 | `zimeiti-review` | 结论 **落实为文件修改** |

**评审原则：G1/G2/G3 之外的一切默认由 AI 自主完成，不打扰你。**
你的每次评审意见，AI 都应沉淀进模板或知识库，避免同样的问题出现第二次。

## 五、常用指令（直接对 AI 说）

| 你说 | AI 做 |
|---|---|
| **"理一下收集箱"** | 并行扫六个雷达源 → 去重归并 → 四维打分 → 写入选题库 → 停在 G1 汇报 Top 5 |
| "加一条想法：xxx" | 只追加到收集箱，不触发全流程 |
| "这周做什么" | 只读选题库推荐，不重新扫描 |
| **"从选题库挑 3 个出方案"** | 取分数最高的，各写一份选题方案，停在 G1 |
| **"把《xx》做到 G2"** | 从方案一路做到正文 + 分镜 + 生图提示词，停在脚本评审 |
| **"《xx》G2 通过，钩子选 B"** | 生成素材（图 + 配音）→ 合成视频 → 停在 G3 |
| "重出第 5 镜" | 单张重生成，自动带上邻近已通过镜作参考 |
| **"《xx》G3 通过"** | 六平台改编 + 发布物料清单，文件夹移入 03_待发布 |
| "发小红书" | 调本地 MCP 发布（**发布前必须再确认一次**） |
| **"复盘"** | 读已发布数据 → 按 K4 定位 → **实际修改选题库/模板** → 记入决策日志 |
| "定位复审" | 满 10 条数据后，汇总分析并更新账号定位（版本号 +0.1） |

## 六、并行调度（subagent fan out）

哪些环节该并行、哪些必须主 Agent 集中做——**这个边界搞错会出乱子**：

| 环节 | 并行 | 说明 |
|---|---|---|
| 选题：六个雷达源 | ✅ 各一个 subagent | 互不依赖 |
| 选题：归并去重 | ❌ **主 Agent** | 需要跨源全局视野，subagent 各看各的会产出大量近似重复 |
| 选题：逐条打分 | ✅ 各一个 subagent | 独立评分更客观 |
| 脚本：3 个钩子备选 | ✅ 各一个 subagent | 用不同钩子类型，避免同质 |
| 脚本：正文创作 | ❌ 串行 | 需要整体节奏感，拆开会散 |
| 脚本：分镜提示词 | ✅ 每 3-4 镜一个 | |
| 脚本：一致性校对 | ❌ **主 Agent** | STYLE/IDENTITY LOCK 的逐字比对必须集中做 |
| 素材：批量生图 | ⚠️ 脚本内并发 3-4 | API 有速率限制，**不要开 12 个 subagent 各自调 API** |
| 素材：生图/配音/卡片 | ✅ 三条线并行 | 互不依赖 |
| 发布：六平台改编 | ✅ 各一个 subagent | 但金句由主 Agent 统一 |
| 复盘：多条各自诊断 | ✅ 各一个 subagent | |
| 复盘：跨条找规律 + 落实修改 | ❌ **主 Agent** | 需全局视野；文件写入必须集中避免冲突 |

**规律**：**发散用并行，收敛用主 Agent。** 任何需要"看到全部结果才能做的判断"都不能交给 subagent。

## 七、信任域（这条决定了什么能在哪跑）

| 环节 | 跑在哪 | 为什么 |
|---|---|---|
| 选题、脚本、分镜、提示词、多平台文案 | **云端会话** | 纯文本，无登录态 |
| 生图 API、配音、视频合成 | 两边都行 | 只需 API Key，不涉及平台账号 |
| **所有发布、所有平台数据抓取** | **只能本地 Windows** | 需要 cookie / 固定 IP 白名单 / 剪映客户端 |

**云端会话绝不持有你的平台 cookie。** 跨境 IP + 代理出口访问平台 = 账号风险。
公众号 API 还额外要求固定 IP 白名单——这条直接决定了公众号发布不可能从云端发出去。

## 八、约定

- **命名**：`YYYY-MM-DD_线_标题`，线 ∈ { 知识线, 故事线 }
- **状态即位置**：`02_制作中` → `03_待发布` → `04_已发布`，文件夹整体移动，不用标记位
- **模板即流程**：想改流程，直接改 `90_模板库/` 里的模板文件
- **知识库即约束**：`91_知识库/` 不是参考读物，是 AI 生成时必须对照的硬规则
- **一鱼多吃**：核心资产只生产一次，六平台全是"改编"不是重写
- **角色资产先行**：新角色必须先出定妆照，不要边做边画
- **发布前必须人工确认**：发出去撤不回来
- **AI 生成内容主动标注**：这是法律要求（2025-09-01 施行），也是我们的人设
- **不编造事实**：拿不准的写"待核实"，发布前查证或删掉

## 九、起号期（前 30 条）的特别提醒

1. **只装一个工具**：小红书 MCP。其余等量上来再说，**装了不用是负债**。
2. **小红书先发**：生产最快，用它验证选题，跑通了再做视频版。
3. **控制变量**：一次只改一个变量（钩子/结构/画风/时长），否则数据无法归因。
4. **前 10 条只看相对值**：冷启动期绝对值没有参考价值。
5. **单条数据不构成结论**：至少 3 条同类表现一致，才动选题库权重。
6. **零预算能做到 80% 的观感**：先把免费链路跑通 10 条，
   再决定往哪加钱——优先级是 **生图质量 > 配音自然度 > 动效**，不是反过来。
